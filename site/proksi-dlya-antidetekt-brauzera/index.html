Как прокси устроены в антидетект-браузере

Антидетект-браузеры изначально рассчитаны на работу с прокси: у каждого профиля свой отпечаток и свои сетевые настройки. При создании профиля указывают тип (HTTP или SOCKS5), адрес, порт, логин и пароль, и многие такие программы сразу проверяют соединение. Поэтому прокси для антидетект браузера задаются внутри него самого. Направлять сам антидетект через ProxyBridge не стоит: получится цепочка из двух прокси, а правило на весь процесс отправит все профили через один адрес, что ломает саму идею разделения.

Как сделать в ProxyBridge

  1. Оставь прокси профилей в настройках антидетект-браузера и не добавляй его процесс в ProxyBridge.
  2. Открой Split Tunnel и добавь через Browse парсер, мессенджер или другую программу рабочего процесса.
  3. Для каждой программы укажи свой прокси, например http://user:pass@ip:port.
  4. Проверь HTTP-прокси кнопкой VERIFY, а SOCKS5 проверь подключением.
  5. Нажми APPLY SPLIT TUNNELING.

Где ProxyBridge полезен рядом с антидетектом

Рабочий процесс редко ограничивается браузером. Вокруг профилей обычно работают программы, у которых нет поля для прокси или где его неудобно менять. Им можно назначить отдельный IP через Split Tunnel:

Для каждой такой программы делается своё правило в Split Tunnel со своим прокси. Остальной трафик компьютера, включая обновления Windows и личные приложения, идёт напрямую и не расходует трафик купленных прокси. Это заметно, если тариф у провайдера посчитан по гигабайтам.

  • парсер или скрипт, который собирает данные по тем же площадкам и должен ходить с отдельного IP, а не с домашнего;
  • десктопный мессенджер для связи с командой или клиентом через рабочий прокси;
  • обычный браузер для почты и таблиц, который ты держишь на одном стабильном адресе, не смешивая с профилями;
  • утилиты рекламных площадок и программы для выгрузки статистики.

Проверь имя процесса

Многие антидетекты построены на Chromium, и их профили запускаются отдельными процессами. Иногда имя такого процесса совпадает с обычным chrome.exe. Если в ProxyBridge есть правило для chrome.exe, оно может захватить и профили антидетекта, и тогда их трафик пойдёт через прокси дважды. Перед настройкой запусти профиль, открой Диспетчер задач, вкладку «Подробности», и посмотри, как называется его процесс. При совпадении не ставь правило на chrome.exe, а для повседневной работы назначь прокси другому браузеру, например Firefox.

Прокси для мультиаккаунтинга: базовые правила

Адреса для вспомогательных программ удобно хранить в одном текстовом файле. В ProxyBridge его открывает Proxy List через Load from File, а последние использованные прокси сохраняются в истории, так что вернуть нужный адрес для парсера или мессенджера можно одним кликом.

  • Один аккаунт, один IP. Не используй одинаковый адрес в разных профилях и в программах рядом с ними.
  • Регион прокси должен совпадать с часовым поясом и языком профиля, это обычно выставляется в самом антидетекте.
  • WebRTC работает по UDP. Антидетекты, как правило, умеют подменять или отключать его в профиле. ProxyBridge передаёт через прокси только TCP, так что у программ вне браузера UDP уходит напрямую.
  • Прокси покупают у провайдера, ProxyBridge их не продаёт. Список провайдеров есть на странице провайдеров на сайте.
  • Не держи включённым VPN: вместе с ProxyBridge он конфликтует.

Частые вопросы

Нужен ли прокси-клиент, если в антидетект-браузере уже есть прокси?

Для самих профилей нет, прокси задаётся в настройках профиля. Клиент нужен для программ вокруг: парсеров, мессенджеров, утилит без поддержки прокси.

Сколько прокси нужно для мультиаккаунтинга?

Обычно по одному IP на аккаунт плюс отдельные адреса для вспомогательных программ, если они обращаются к тем же сервисам. Точное число зависит от площадки и её правил.

Почему профиль антидетекта стал медленным после установки ProxyBridge?

Вероятно, правило Split Tunnel захватило процесс профиля, и трафик идёт через два прокси. Проверь имя процесса в Диспетчере задач и убери пересекающееся правило.
