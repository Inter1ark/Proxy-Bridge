Прокси для всей системы Windows

Почему системный прокси Windows не работает в программах

Прокси для всей системы Windows в привычном смысле не существует. Настройка в «Параметрах» записывает адрес в системные параметры, а дальше каждая программа сама решает, читать их или нет. Edge и Chrome читают. Многие мессенджеры, торговые терминалы, клиенты на Java, консольные утилиты вроде curl без флагов и программы с собственным сетевым кодом не читают и подключаются напрямую. Отсюда частый запрос «системный прокси windows не работает в программах»: он работает, просто только там, где программа согласна его использовать. Есть ещё отдельная настройка WinHTTP, которую меняют командой netsh winhttp set proxy. Её читают в основном системные службы, а не обычные программы, так что в Windows фактически две разные настройки прокси, и ни одна не обязательна для приложений.

ProxyBridge не просит согласия. Драйвер WinDivert видит исходящие соединения всех процессов и отправляет их в выбранный HTTP или SOCKS5 прокси. Весь трафик через прокси здесь означает весь TCP-трафик, независимо от того, есть ли у программы настройки. Чтобы включить такой режим, на вкладке «Главная» не добавляй строк с программами, а в строке «Все остальные программы» выбери нужный прокси.

Как сделать в ProxyBridge

  1. Вставь адрес прокси на вкладке «Прокси» и нажми «Добавить».
  2. Нажми «Проверить», чтобы увидеть задержку, страну и внешний IP.
  3. На вкладке «Главная» в строке «Все остальные программы» выбери этот прокси, строки программ не добавляй.
  4. Нажми «Подключить» и проверь внешний IP на любом сайте проверки адреса.
  5. Если подключение нужно постоянно, включи на вкладке «Настройки» запуск вместе с Windows и подключение при запуске.

Что именно пойдёт через прокси

Через прокси идут TCP-соединения: веб-страницы, API, почта, загрузки, большинство рабочих приложений. UDP идёт напрямую, а на нём работают голосовые и видеозвонки, многие онлайн-игры, часть потокового видео. DNS-запросы (порт 53) всегда уходят напрямую, отдельной настройки для этого нет. Про то, как это влияет на результат проверки IP, есть отдельная статья про утечку DNS. Если провайдер прокси считает трафик, учти, что в системном режиме через прокси уходят и фоновые загрузки: обновления Windows, синхронизация облачных дисков, обновления программ. Для экономии трафика больше подходит режим по программам.

Системный режим на практике

Представь ноутбук сотрудника, которому служба безопасности выдала прокси с логином и паролем. Браузер через «Параметры» Windows настраивается за минуту, но клиент CRM, торговый терминал и утилита синхронизации файлов продолжают ходить напрямую и упираются в запрет на сетевом экране компании. В системном режиме ProxyBridge все они начинают выходить через прокси без отдельной настройки. Другой случай: тестировщик проверяет, как интернет-магазин показывает цены и доставку для другого региона, и хочет, чтобы и браузер, и десктопное приложение магазина видели один и тот же адрес. Одна кнопка «Подключить» даёт это сразу для всего компьютера. В обоих случаях не нужно помнить, какая программа читает системный прокси, а какая нет.

Какие задачи решает

  • Выход всего компьютера через корпоративный прокси, когда этого требует политика компании.
  • Проверка сайта или приложения так, будто компьютер находится в другом регионе.
  • Работа с сервисом, который пускает только с белого IP прокси.
  • Подключение программ, которые игнорируют системный прокси Windows.
  • Единый внешний IP для всех рабочих программ без настройки каждой.

Как держать подключение постоянно

На вкладке «Настройки» есть четыре полезных переключателя: запуск вместе с Windows, подключение при запуске, сворачивание в трей при закрытии и уведомления о подключении и отключении. Вместе они дают поведение, близкое к «включил один раз и забыл», а новые версии программа проверяет сама и ставит после твоего подтверждения. Внизу главного окна видны задержка до прокси и счётчики полученного и отправленного трафика, по ним легко заметить, что прокси перестал отвечать. Если прокси нужен только в рабочее время, автозапуск можно не включать, а запускать программу и нажимать «Подключить» вручную.

VPN-клиент вроде WireGuard или AmneziaWG выключать не нужно: ProxyBridge работает вместе с ним. А вот прокси перед подключением стоит проверить кнопкой «Проверить» на вкладке «Прокси»: если он не отвечает, в этом режиме пострадают соединения всего компьютера, а не одной программы.

Уточнение: режим «весь компьютер» даёт один прокси для строки «Все остальные программы», а если разным программам нужны разные адреса или часть программ должна идти напрямую, добавь для них отдельные строки кнопкой «Добавить программу».

Частые вопросы

Как пустить весь трафик через прокси в Windows 11?

Встроенная настройка прокси действует только на программы, которые её читают. Чтобы через прокси шёл весь TCP-трафик, нужен клиент с перехватом на уровне драйвера, например ProxyBridge с прокси в строке «Все остальные программы».

Почему после включения прокси в Windows программа всё равно показывает мой IP?

Скорее всего, программа не использует системные настройки прокси и подключается напрямую. Также проверь, не работает ли она по UDP: такой трафик через прокси не идёт.

Пойдут ли обновления Windows через прокси в системном режиме?

Да, если они идут по TCP, а это обычный случай. Если обновления не должны тратить трафик прокси, добавь нужные программы отдельными строками, а «Все остальные программы» переключи на «Напрямую».
