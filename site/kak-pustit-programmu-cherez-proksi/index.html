Как пустить программу через прокси, если в ней нет настроек прокси

Многие программы для Windows не умеют работать с прокси: в настройках просто нет нужного поля. ProxyBridge перехватывает трафик на уровне сетевого драйвера и отправляет его в прокси принудительно, без правок в самой программе. Ниже показано, как это сделать за пару минут.

Почему программа игнорирует прокси

Пустить программу через прокси просто, если у неё есть свои сетевые настройки: браузеры, Telegram Desktop и многие парсеры умеют это сами. Сложности начинаются с программами без настроек прокси: консольные утилиты, старые корпоративные клиенты, самописные скрипты, лаунчеры и модули обновления. Часть из них не читает и системный прокси Windows, потому что открывает соединения напрямую через сетевой стек. Указать адрес в Параметрах Windows в таком случае бесполезно: программа эту настройку просто не спрашивает, и трафик уходит с твоего обычного IP.

Как сделать в ProxyBridge

  1. Установи ProxyBridge от имени администратора и введи ключ при первом запуске.
  2. Переключись в режим Split Tunnel и добавь программу через Browse или впиши имя процесса.
  3. Вставь для неё прокси в формате socks5://user:pass@ip:port, http://user:pass@ip:port или ip:port:user:pass.
  4. Нажми APPLY SPLIT TUNNELING и при необходимости перезапусти программу, чтобы она открыла новые соединения.
  5. Проверь внешний IP через саму программу или по логам сервиса, к которому она подключается.

Как работает принудительный режим

ProxyBridge ставит драйвер WinDivert и видит исходящие TCP-соединения всех процессов. В режиме Split Tunnel ты добавляешь правило: имя процесса, например app.exe, и прокси, через который он должен ходить. Драйвер забирает соединения именно этого процесса и отправляет их в HTTP или SOCKS5 прокси, а остальные программы продолжают работать напрямую. Самой программе ничего не нужно знать о прокси: для неё соединение выглядит обычным. Так что способ подходит и для программ без поля прокси, и для тех, где поле есть, но логин и пароль оно не принимает.

  • консольные утилиты и скрипты на Python, Node.js или Go;
  • клиенты внутренних систем, которые должны выходить через корпоративный прокси;
  • парсеры и SEO-программы без поддержки SOCKS5 с авторизацией;
  • любой .exe, у которого сетевые настройки спрятаны или отсутствуют.

Этот вариант нужен, когда простые способы не сработали: поля для прокси нет, системный прокси программа игнорирует, а пускать через прокси весь компьютер в системном режиме ты не хочешь.

Ограничения, о которых стоит знать

Через прокси идёт только TCP. Если программа отправляет данные по UDP (голосовые звонки, многие онлайн-игры, часть видео), этот трафик пойдёт напрямую, поэтому для игр и звонков способ не подходит. DNS-запросы по умолчанию тоже идут напрямую, за это отвечает настройка DNS Bypass. С запущенным VPN-клиентом программа работает плохо: два перехватчика трафика мешают друг другу, VPN на это время нужно выключить. И ещё: правило привязано к имени процесса, поэтому если программа запускает вспомогательный процесс с другим именем, добавь правило и для него.

Частые вопросы

Как запустить программу через прокси, если в ней нет настроек?

Нужен инструмент, который перехватывает трафик снаружи программы. В ProxyBridge это правило Split Tunnel по имени процесса: сама программа не меняется, а её TCP-соединения идут через указанный прокси.

Можно ли принудительно пустить через прокси игру?

Только частично. Игровые данные обычно передаются по UDP, а ProxyBridge направляет в прокси только TCP, поэтому для игр программу не рекомендуем.

Работает ли это с консольными программами?

Да, правилу неважно, есть ли у программы окно, достаточно знать имя процесса, например curl.exe. Учти, что правило для python.exe затронет все скрипты, запущенные этим интерпретатором.
