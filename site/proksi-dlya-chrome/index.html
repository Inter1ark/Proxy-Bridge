Прокси для Google Chrome

Хочешь пустить Chrome через прокси, а остальные программы оставить на обычном подключении? Ниже встроенные способы и их ограничения, а затем настройка, при которой ProxyBridge назначает прокси только процессу chrome.exe.

Где в Chrome настройки прокси

Своего окна для прокси у Chrome нет. Если открыть «Настройки», раздел «Система» и пункт «Открыть настройки прокси-сервера для компьютера», браузер просто отправит тебя в параметры Windows. То есть прокси для Chrome по умолчанию тот же, что и у всей системы: что указано в Windows, то и использует браузер. Чтобы понять, как подключить прокси в хроме и не задеть остальное, полезно знать три пути: системный прокси, флаг запуска и расширение. У каждого есть свои ограничения.

Как сделать в ProxyBridge

  1. Установи ProxyBridge от имени администратора и введи ключ при первом запуске.
  2. Открой вкладку «Прокси», вставь адрес вида socks5://user:pass@ip:port, нажми «Добавить», а затем «Проверить».
  3. На вкладке «Главная» нажми «Добавить программу» и выбери Chrome из списка запущенных программ.
  4. Справа в строке chrome.exe выбери этот прокси, а в строке «Все остальные программы» оставь «Напрямую».
  5. Нажми «Подключить» и перезапусти Chrome, чтобы через прокси пошли и уже открытые соединения.

Три встроенных способа и их минусы

Если прокси у тебя HTTP без пароля и нужен разово, флага хватит. Сложности начинаются, когда провайдер выдал SOCKS5 с авторизацией, когда Chrome должен работать на одном IP, а другая программа на другом, и когда не хочется трогать системные настройки, от которых зависят остальные приложения.

  • Системный прокси Windows: «Параметры», «Сеть и Интернет», «Прокси-сервер», ручная настройка. Влияет на все программы, которые читают системные настройки, а не только на Chrome. Полей для логина и пароля нет, форма рассчитана на HTTP-прокси.
  • Флаг запуска: в свойствах ярлыка после пути к chrome.exe дописывают --proxy-server="socks5://ip:port". Флаг срабатывает только для нового экземпляра браузера: если Chrome уже открыт, новое окно присоединится к старому процессу без флага. Поэтому его ставят вместе с отдельной папкой профиля через --user-data-dir. Логин и пароль для SOCKS5 так не передать.
  • Расширение-менеджер прокси: удобно переключать адреса прямо в браузере, но SOCKS5 с паролем движок Chrome не поддерживает и через расширения, а самому расширению приходится давать доступ ко всем сайтам.

Chrome через прокси: отдельная строка для chrome.exe

ProxyBridge перехватывает соединения на уровне сетевого драйвера, поэтому Chrome не нужны ни флаги, ни расширения. На вкладке «Главная» ты добавляешь программу chrome.exe и справа в её строке выбираешь прокси, сохранённый на вкладке «Прокси» в формате socks5://user:pass@ip:port, http://user:pass@ip:port или ip:port:user:pass. Логин и пароль работают для обоих протоколов. Вкладки, расширения и служебные процессы Chrome называются chrome.exe, так что под правило попадает весь браузер. Остальные программы идут напрямую через строку «Все остальные программы» или через свои правила: например, Chrome на одном прокси, парсер на другом, мессенджер без прокси. Такой режим по программам ещё называют split tunneling.

Прокси перед подключением можно проверить кнопкой «Проверить» на вкладке «Прокси»: проверка идёт через сам прокси, для HTTP и SOCKS5, и показывает задержку, внешний IP, страну и город. Строка «Как идёт трафик» на главной простыми словами описывает, что сейчас идёт через прокси, а что напрямую.

Что учесть, чтобы не было сюрпризов

  • Через прокси идёт только TCP. Chrome часто соединяется с сайтами по протоколу QUIC, а он работает поверх UDP и уйдёт напрямую. Чтобы этого не было, в chrome://flags отключи пункт Experimental QUIC protocol.
  • WebRTC тоже использует UDP и может показать сайту реальный IP. Встроенного переключателя в Chrome нет, поставь расширение, ограничивающее WebRTC, и проверь результат на сайте проверки утечек.
  • DNS-запросы в ProxyBridge всегда идут напрямую, отдельной настройки для этого нет.
  • VPN выключать не нужно: ProxyBridge работает вместе с VPN-клиентами вроде WireGuard и AmneziaWG. А вот системный прокси Windows или флаг --proxy-server убери, чтобы не получилась цепочка из двух прокси.

Частые вопросы

Как подключить прокси в хроме с логином и паролем?

Для HTTP-прокси Chrome сам покажет окно авторизации. SOCKS5 с логином и паролем браузер не поддерживает ни флагом, ни через Windows, поэтому нужен внешний клиент, например ProxyBridge с форматом socks5://user:pass@ip:port.

Можно ли включить прокси только для Chrome, а не для всего компьютера?

Да. Штатно это делает флаг --proxy-server с отдельным профилем или расширение, в ProxyBridge отдельная строка для chrome.exe на вкладке «Главная». Остальной трафик при этом идёт напрямую.

Почему сайт видит реальный IP, хотя chrome через прокси?

Чаще всего причина в QUIC или WebRTC: оба работают по UDP, а он идёт мимо прокси. Отключи QUIC в chrome://flags, ограничь WebRTC расширением и проверь ещё раз.
