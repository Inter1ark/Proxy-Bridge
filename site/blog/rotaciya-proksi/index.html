Ротация прокси: когда она нужна и как переключаться вручную

Ротация прокси помогает в сборе данных и мешает, когда речь об аккаунтах. Объясняем, как устроена смена IP у провайдеров и как переключаться между адресами вручную, если клиент не меняет их сам.

Что называют ротацией

Ротация прокси это смена внешнего IP-адреса, с которого твои запросы приходят на сайт. Технически она бывает трёх видов. В первом случае адрес меняется на каждом новом соединении. Во втором провайдер держит один IP заданное время (такие сессии называют липкими, sticky), а потом выдаёт следующий. В третьем адрес меняется по команде: ты открываешь служебную ссылку или вызываешь API, и прокси получает новый IP. Последний вариант типичен для мобильных прокси, где смена адреса связана с переподключением модема к сети оператора.

Есть и ручная ротация в широком смысле: у тебя список статических прокси, и ты сам выбираешь, через какой из них работать сейчас. Формально это не ротация провайдера, но задачи она решает похожие, особенно когда адресов немного и важно понимать, какой из них сейчас в работе.

Когда смена IP действительно нужна

Ротация полезна там, где много однотипных запросов идёт к одному сайту и их нужно распределить по адресам. Типичные примеры: мониторинг цен в каталогах, сбор позиций в поисковой выдаче из разных регионов, проверка того, как сайт отображается пользователям из разных городов, массовая проверка ссылок. С одного IP такие запросы быстро упираются в ограничения частоты, которые сайт вводит для защиты от нагрузки.

При этом ротация не отменяет правил сайта. Если в robots.txt или в условиях использования сбор данных ограничен, смена адресов этого не меняет. Разумная схема выглядит так: умеренная частота запросов, паузы, кэширование уже полученных страниц и смена IP как способ распределить нагрузку, а не как способ спорить с явным запретом владельца сайта.

Когда ротация вредит

Всё, что связано с сессией, плохо переносит смену адреса. Если ты вошёл в аккаунт, а через минуту следующий запрос пришёл с другого IP из другого города, площадка воспримет это как подозрительный вход: попросит подтверждение, завершит сессию или ограничит действия. То же касается корзин в интернет-магазинах, платёжных форм, личных кабинетов банков и сервисов, которые запоминают устройство.

Вторая проблема чисто техническая. Длинное TCP-соединение (загрузка большого файла, потоковые данные, долгий веб-сокет) живёт на одном адресе. Если провайдер сменил IP посреди соединения, оно оборвётся, и программа начнёт переподключаться. Поэтому для аккаунтов и долгих сессий выбирают статические прокси или липкие сессии с достаточным временем жизни.

  • работа в личных кабинетах и рекламных аккаунтах;
  • оплата и любые формы с подтверждением;
  • загрузка крупных файлов и долгие соединения;
  • сервисы, которые запоминают устройство и IP при входе.

Как ротация устроена на стороне провайдера

Большинство провайдеров с ротацией выдают не список адресов, а одну точку входа: хост и порт шлюза. Ты подключаешься к ней как к обычному прокси, а шлюз сам выбирает выходной IP из пула. Параметры ротации обычно задаются в логине: в имени пользователя указывают страну, город или идентификатор сессии, и шлюз держит один IP, пока идентификатор не изменится. Другие провайдеры выделяют отдельные порты под разные режимы. Точный формат у каждого свой, его стоит посмотреть в личном кабинете или документации. У мобильных прокси смена по ссылке занимает время, пока модем переподключается, и в этот момент соединения через прокси недоступны: программа должна уметь подождать и повторить запрос.

Для клиента на компьютере это удобно: в его настройках прописан один и тот же адрес, а смена IP происходит по ту сторону. Неудобно другое: ты не всегда знаешь, какой адрес сейчас выходной, и разные соединения одной программы могут уйти с разных IP. Для парсинга это нормально, для работы в одной вкладке с авторизацией нет.

Ручное переключение в ProxyBridge

В ProxyBridge нет автоматической ротации: программа не меняет прокси по таймеру и не перебирает адреса сама. Переключение делается вручную, и для этого есть два удобных места. Proxy List загружает список прокси из текстового файла через Load from File, после чего к любому адресу из списка подключаешься кнопкой Connect. История прокси хранит последние использованные адреса, клик по записи подставляет прокси в поле.

После переключения на HTTP-прокси нажми VERIFY: программа покажет внешний IP, страну и город, так что сразу видно, что смена произошла. SOCKS5 через VERIFY не проверяется, его проверяют подключением, например открыв сайт определения IP. Учти, что уже открытые соединения программ могут оборваться при смене маршрута, поэтому после переключения иногда стоит обновить вкладку или перезапустить приложение.

  • подготовь текстовый файл, по одному прокси в строке, в формате ip:port:user:pass или с префиксом http:// или socks5://;
  • загрузи файл в Proxy List через Load from File;
  • подключайся к нужному адресу кнопкой Connect и переходи к следующему, когда этого требует задача;
  • для HTTP-прокси проверяй смену адреса через VERIFY.

Ротирующий шлюз провайдера через ProxyBridge

Если автоматическая смена IP всё же нужна, её проще взять у провайдера. Укажи в ProxyBridge адрес ротирующего шлюза как обычный прокси, с логином и паролем из личного кабинета. Программа будет отправлять соединения в шлюз, а он сам распределит их по адресам из пула. В системном режиме через шлюз пойдёт весь TCP-трафик, в режиме Split Tunnel только выбранные программы, например парсер, а браузер с аккаунтами останется на статическом прокси или пойдёт напрямую.

Здесь важно правильно читать результат VERIFY: он показывает адрес на момент проверки. При ротации на каждое соединение следующий запрос программы может выйти уже с другого IP, и это ожидаемое поведение, а не ошибка. Если нужно, чтобы адрес держался дольше, выбери у провайдера липкую сессию.

Сколько адресов нужно для ручного перебора

При ручном переключении количество адресов считается от задачи, а не от желания иметь побольше. Для проверки выдачи по регионам нужен хотя бы один адрес в каждом нужном городе. Для мониторинга нескольких сайтов с умеренной частотой хватает небольшого списка, между адресами которого ты переключаешься по расписанию. Если переключаться приходится каждые несколько минут, это сигнал, что ручная схема уже не справляется и пора смотреть на ротирующий шлюз провайдера или на скрипт, который сам управляет прокси в своём коде.

Учитывай и модель оплаты. Статические адреса обычно оплачиваются поштучно за срок, а пул с ротацией чаще считается по трафику. Для небольших объёмов выгоднее короткий список статических прокси, для массового сбора данных удобнее пул.

Как не запутаться в адресах

Когда прокси много, путаница обходится дороже самих адресов. Держи отдельный файл для каждой задачи: список для парсинга, список для проверки выдачи по регионам, закреплённые адреса для аккаунтов. Записывай в таблицу, какой IP за чем закреплён и до какого числа оплачен. Не бери адреса из списка для аккаунтов в задачи с частым перебором: так закреплённый IP не засветится там, где идут тысячи запросов. Тогда ручное переключение остаётся предсказуемым, а ротирующий шлюз работает только там, где он действительно нужен.

Частые вопросы

Есть ли в ProxyBridge автоматическая ротация прокси?

Нет, программа не меняет адреса сама. Переключаться можно вручную через Proxy List и историю прокси или подключить ротирующий шлюз провайдера, который меняет IP на своей стороне.

Как часто менять IP при парсинге?

Универсального значения нет: оно зависит от ограничений сайта и частоты запросов. Начни с умеренной скорости и пауз, а ротацию используй, чтобы распределить нагрузку.

Подходит ли ротация прокси для аккаунтов?

Обычно нет. Для аккаунтов нужен стабильный адрес, а смена IP посреди сессии вызывает проверки и выход из аккаунта.
