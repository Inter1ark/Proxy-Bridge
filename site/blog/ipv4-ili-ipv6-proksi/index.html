IPv4 или IPv6 прокси: что выбрать для программ на Windows

IPv6-прокси дешевле и их больше, но работают они не со всеми сайтами и программами. Разбираем, чем отличаются оба варианта, где IPv6 даёт выгоду и почему для большинства задач на Windows проще взять IPv4.

Чем различаются IPv4 и IPv6

Вопрос «IPv4 или IPv6 прокси» почти всегда сводится к цене и совместимости. Адресов IPv4 всего около 4,3 миллиарда, и свободных среди них давно нет: провайдеры покупают и арендуют их на вторичном рынке, поэтому каждый IPv4-прокси стоит заметных денег. В IPv6 адресное пространство огромное, один сервер может получить целые блоки адресов, и продавцы выдают IPv6-прокси сотнями по цене нескольких IPv4.

Внешне разница видна в записи адреса: IPv4 это четыре числа через точку, IPv6 длинная строка из шестнадцатеричных групп через двоеточие. Но важнее не формат, а то, может ли сайт вообще принять соединение по IPv6 и умеет ли твоя программа с таким адресом работать. Здесь и начинаются ограничения.

Главное ограничение: не каждый сайт доступен по IPv6

Чтобы к сайту можно было подключиться по IPv6, у его домена должна быть AAAA-запись, а сервер должен принимать такие соединения. Крупные платформы и CDN давно это поддерживают, а многие небольшие сайты, региональные магазины, старые API и корпоративные сервисы доступны только по IPv4. Если прокси выходит в интернет исключительно через IPv6, такой сайт для него просто не откроется: соединение не установится, программа покажет ошибку или будет бесконечно грузиться. Проверить, есть ли у сайта IPv6, можно командой nslookup с типом записи AAAA: если в ответе нет ни одного IPv6-адреса, через прокси с выходом только по IPv6 сайт недоступен.

Некоторые провайдеры решают это так: если у сайта нет IPv6, соединение выпускается через общий IPv4-адрес. Сайт открывается, но уже не с твоего выделенного адреса. Как именно ведёт себя конкретный тариф, нужно уточнять у продавца заранее, иначе в проверках и статистике появится неожиданная картина.

Вход и выход: два разных адреса

У любого прокси есть адрес, к которому подключаешься ты, и адрес, с которого он выходит в интернет. Они не обязаны совпадать по версии протокола. Частая схема у IPv6-прокси: точка входа на IPv4 (обычный ip:port), а выход идёт с выделенного IPv6. Это удобно, потому что у многих домашних и офисных подключений IPv6 нет, и к IPv6-адресу напрямую ты бы не подключился.

Перед покупкой уточни оба адреса. Если продавец даёт точку входа только по IPv6, проверь, есть ли IPv6 у твоего интернет-провайдера: без него прокси будет недоступен с твоего компьютера вовсе. Для ввода в программы адрес входа на IPv4 тоже проще. Строки вида ip:port:user:pass используют двоеточие как разделитель, а в IPv6-адресе двоеточий много, и не каждая программа разберёт такую запись правильно.

Отдельно стоит помнить про DNS. Клиенты с перехватом на уровне сети передают в прокси уже IP-адрес, который программа получила при разрешении имени, а не само имя сайта. Если компьютер работает только по IPv4, программа выберет IPv4-адрес сайта, и прокси с выходом исключительно по IPv6 не сможет к нему подключиться, даже если у сайта есть и IPv6. Программы, которые сами поддерживают SOCKS5, часто умеют передавать прокси имя хоста, и тогда версию адреса выбирает прокси.

Скорость и стабильность

Сама версия протокола на скорость почти не влияет: задержку определяют расположение сервера, загрузка канала и маршрут до него. Разница возникает косвенно. Недорогие IPv6-тарифы могут продаваться крупными партиями с одного сервера, и если на нём много клиентов, канал делится между всеми. IPv4-адреса у того же продавца могут жить на других серверах с другой нагрузкой. Поэтому сравнивать стоит не версии протокола, а конкретные тарифы на твоей задаче: возьми по одному тестовому адресу каждого типа и прогони одинаковый сценарий.

Программы на Windows и двойной стек

Если у подключения есть и IPv4, и IPv6, Windows по умолчанию предпочитает IPv6 для сайтов, которые его поддерживают. Для прокси это важно. Программа, настроенная на прокси, отправит соединение в прокси, и версия протокола дальше решается на его стороне. А программа, которая прокси не использует, пойдёт к сайту напрямую, и нередко именно по IPv6, мимо всех твоих настроек.

С клиентами, которые перехватывают трафик, стоит отдельно проверить, какие соединения они обрабатывают. Перехват в ProxyBridge рассчитан на IPv4-соединения программ, поэтому, если у тебя дома включён IPv6, проверь результат: открой в нужной программе сайт определения IP и убедись, что видишь адрес прокси, а не своего провайдера. Если сайт показывает твой собственный IPv6, часть трафика идёт напрямую. В этом случае можно отключить протокол IPv6 в свойствах сетевого адаптера на время работы через прокси.

Когда IPv6-прокси выгоден

IPv6 хорошо работает там, где нужна большая партия адресов под площадку, которая точно поддерживает IPv6. Это сбор данных с крупных сервисов, проверка выдачи и отображения сайта, тестирование собственного сайта, если он настроен на IPv6. Низкая цена адреса позволяет распределить запросы шире, чем на нескольких IPv4, и не экономить на каждом потоке.

Есть нюанс, о котором продавцы пишут редко. IPv6-адреса раздаются блоками, и сайты нередко оценивают не отдельный адрес, а целую подсеть. Если сотни твоих адресов лежат в одной подсети /64, для системы защиты от ботов они могут выглядеть как один источник. Поэтому большое количество IPv6 не всегда превращается в такое же количество независимых адресов, и перед закупкой партии стоит спросить, из скольких подсетей она набрана.

Когда нужен IPv4

Для большинства задач на Windows IPv4 остаётся вариантом по умолчанию. Он дороже, но совместим со всем: с любым сайтом, любой программой и любым форматом ввода. IPv4 стоит брать в таких случаях:

  • работа в аккаунтах, где важен стабильный и привычный для площадки адрес;
  • небольшие сайты, региональные сервисы и API без поддержки IPv6;
  • программы, которые не понимают IPv6-адреса в настройках или в строке подключения;
  • задачи, где важна точная геолокация: для IPv4 базы геолокации обычно подробнее;
  • любые ситуации, когда нет уверенности, что целевой сайт поддерживает IPv6.

Как проверить прокси до того, как строить на нём работу

Проверка занимает несколько минут и отвечает на главный вопрос: работает ли конкретный адрес с конкретными сайтами из твоей задачи. Начни с одного-двух адресов из партии, а уже потом настраивай всё остальное.

  • подключись к прокси и открой сайт определения IP: посмотри, какой адрес и какой версии видит сайт;
  • открой два-три сайта, с которыми будешь работать, особенно небольшие: если какой-то не грузится, вероятно, у него нет IPv6;
  • сравни геолокацию в паре разных сервисов проверки IP;
  • в ProxyBridge нажми «Проверить» на вкладке «Прокси» и посмотри задержку, страну, город и внешний IP, проверка работает и для HTTP, и для SOCKS5;
  • если дома есть IPv6, убедись, что программы не выходят в сеть напрямую со своего адреса.

Частые вопросы

Что выбрать для парсинга: IPv4 или IPv6 прокси?

Если целевой сайт поддерживает IPv6, IPv6-прокси дадут больше адресов за те же деньги. Если нет или ты не уверен, бери IPv4: с ним сайт откроется в любом случае.

Почему сайт не открывается через IPv6 прокси?

Скорее всего, у сайта нет IPv6-адреса, и прокси с выходом только по IPv6 не может к нему подключиться. Уточни у продавца, есть ли выход через IPv4 для таких сайтов, или возьми IPv4-прокси.

Можно ли пользоваться IPv6 прокси без IPv6 у провайдера?

Да, если точка входа прокси на IPv4: ты подключаешься по IPv4, а прокси выходит в сеть по IPv6. Если вход тоже только по IPv6, без его поддержки у твоего провайдера подключиться не получится.
