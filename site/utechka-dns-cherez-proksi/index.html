Утечка DNS при работе через прокси

Сайт видит IP прокси, а тест показывает DNS-сервер твоего провайдера. Это и называют утечкой DNS. Ниже честно о том, откуда она берётся, как ProxyBridge работает с DNS и когда это действительно важно.

Что такое утечка DNS

Перед подключением к сайту компьютер спрашивает у DNS-сервера, какой IP у домена. Обычно этот запрос идёт по UDP на порт 53 к серверу, который выдал провайдер или который указан в настройках Windows. Утечкой DNS (DNS leak) называют ситуацию, когда сами соединения идут через прокси, а DNS-запросы уходят напрямую. Сервисы проверки видят два разных источника: IP прокси у соединения и DNS-резолвер из твоей сети. Для сайта это признак того, что запросы приходят из одного места, а имена разрешаются в другом.

Как сделать в ProxyBridge

  1. Подключись к прокси кнопкой CONNECT в системном режиме.
  2. Открой Settings и посмотри состояние настройки DNS Bypass.
  3. Запусти в браузере любой тест DNS leak и сравни IP соединения с адресами DNS-серверов.
  4. Если регион резолвера важен, включи в браузере DNS поверх HTTPS.
  5. Повтори тест и убедись, что DNS-сервер в отчёте сменился.

Как ProxyBridge работает с DNS

По умолчанию ProxyBridge отправляет DNS-запросы напрямую, мимо прокси. Это поведение связано с настройкой DNS Bypass в Settings. Причина практическая: через прокси программа направляет только TCP, а классический DNS работает по UDP. Значит, тест на утечку DNS в системном режиме, скорее всего, покажет DNS-сервер провайдера или тот, что задан в Windows. Соединения с сайтами при этом идут через прокси, и сайт видит IP прокси. Скрывать это поведение мы не будем: DNS через прокси по умолчанию не идёт.

  • задай в Windows публичный DNS-сервер вместо провайдерского: это меняет резолвер, но не маршрут запросов;
  • включи в браузере DNS поверх HTTPS: такие запросы идут по TCP и вместе с остальным трафиком попадают в прокси;
  • в антидетект-браузере посмотри, как профиль обрабатывает DNS, у многих это настраивается отдельно.

Когда это важно, а когда нет

Для большинства рабочих задач утечка DNS не мешает: корпоративный прокси, проверка региональной выдачи, разделение трафика программ. Сайт видит IP прокси и отдаёт контент для этого адреса. Значение она имеет там, где сервис сравнивает регион соединения и регион DNS: в мультиаккаунтинге и при тестировании геозависимых функций. Если совпадение регионов нужно, проверь его тестом заранее, а не после того, как аккаунт уже создан. И отдельно: прокси сам по себе не делает работу в сети приватной и не прячет трафик от провайдера, этого не обещает ни ProxyBridge, ни любой другой прокси-клиент.

Частые вопросы

Идёт ли DNS через прокси в ProxyBridge?

По умолчанию нет: DNS-запросы идут напрямую, это связано с настройкой DNS Bypass. Через прокси направляется TCP-трафик, а классический DNS работает по UDP.

Как проверить утечку DNS?

Подключись к прокси и открой любой сервис проверки DNS leak. Если в отчёте DNS-серверы твоего провайдера, а IP соединения принадлежит прокси, DNS-запросы идут напрямую.

Опасна ли утечка DNS при работе через прокси?

Для задач вроде корпоративного прокси или парсинга обычно нет. Она важна, когда сервис сверяет регион DNS и регион IP, например при мультиаккаунтинге.
