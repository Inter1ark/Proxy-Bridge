Прокси для отдельных программ (Split Tunnel)

Не всегда нужно пускать через прокси весь компьютер. В режиме по программам (его ещё называют split tunneling) ProxyBridge направляет через прокси только выбранные программы, и каждой можно дать свой адрес.

Как работает прокси для отдельной программы

Прокси для отдельной программы в ProxyBridge задаётся строкой в таблице на вкладке «Главная». Ты нажимаешь «Добавить программу» и выбираешь приложение из списка запущенных или находишь его exe через «Выбрать файл...», например chrome.exe, telegram.exe или python.exe, а справа в строке выбираешь для него прокси. Изменение сохраняется и применяется сразу, даже во время подключения. TCP-соединения этого процесса идут через назначенный прокси, а всё, что не попало в таблицу, подчиняется строке «Все остальные программы»: если там стоит «Напрямую», остальной трафик идёт как без программы.

Самой программе ничего настраивать не нужно. Это главное отличие от встроенных средств: в Windows нет штатного способа направить через прокси одно приложение, а системная настройка прокси общая для всех и к тому же учитывается не каждой программой.

Как сделать в ProxyBridge

  1. Добавь нужные прокси на вкладке «Прокси» и проверь их кнопкой «Проверить все».
  2. На вкладке «Главная» нажми «Добавить программу» и выбери chrome.exe из списка запущенных или через «Выбрать файл...».
  3. Справа в строке выбери прокси для этой программы.
  4. Повтори для других программ, если им нужны свои прокси, а в строке «Все остальные программы» оставь «Напрямую».
  5. Нажми «Подключить» и проверь IP в каждой программе.

Почему не хватает встроенных средств

У некоторых программ есть свои настройки прокси: у Firefox, Telegram Desktop, многих антидетект-браузеров. Но каждая настраивается в своём окне, поддержка SOCKS5 и паролей в них разная, а когда прокси меняется, править приходится везде. У остальных программ поля для прокси нет совсем. Таблица на вкладке «Главная» собирает все правила в одном месте и работает одинаково для любого процесса, будь то браузер или консольная утилита.

Разные прокси для разных программ

Split tunneling прокси раскрывается, когда процессов несколько. Пример рабочего стола арбитражника: антидетект-браузер идёт через резидентный прокси одной страны, парсер на Python через серверный прокси другой, а мессенджер, почта и обновления Windows напрямую, не расходуя трафик провайдера. Другой пример: тестировщик держит Firefox на прокси одного региона, а Chrome на прокси другого и сравнивает выдачу сайта рядом, в двух окнах. А разработчик может пустить через прокси только node.exe с тестами API, не трогая IDE и браузер.

  • Правило привязано к имени процесса, поэтому все окна и копии одного exe получают один и тот же прокси.
  • Если программа запускает вспомогательные процессы с другим именем, например отдельный модуль обновлений, их нужно добавить отдельным правилом.
  • Отдельной кнопки применения нет: изменения в таблице работают сразу, а строку можно временно выключить переключателем, не удаляя её.

Как узнать имя процесса

Имя процесса не всегда совпадает с названием программы. Надёжнее всего открыть «Диспетчер задач», вкладку «Подробности», и найти программу в столбце «Имя». Там видно, например, что Яндекс Браузер работает как browser.exe, а Telegram Desktop как telegram.exe. Обычно эта проверка и не нужна: «Добавить программу» показывает список запущенных программ, а для остальных есть «Выбрать файл...», где exe выбирается в проводнике и имя подставляется само. Если программа установлена в профиль пользователя, её exe обычно лежит в скрытой папке AppData, поэтому проще запустить её и выбрать из списка запущенных.

Какие задачи решает

  • Направить программу через прокси, когда в ней нет поля для прокси.
  • Дать нескольким программам разные IP на одном компьютере.
  • Экономить трафик прокси, оставив фоновые программы и обновления напрямую.
  • Разделить рабочий и личный трафик без двух компьютеров.
  • Пустить через прокси скрипт или консольную утилиту без правки кода.

Ограничения Split Tunnel

Режим работает только с TCP: UDP-трафик выбранной программы, если он есть, пойдёт напрямую, поэтому звонки и игры так не проксируются. Правила задаются по процессу целиком, условий вида «только для такого-то сайта» или «только для порта 443» нет. Режим по программам есть только в версии для Windows, в бете для macOS работает одна строка «Все остальные программы». С VPN-клиентами вроде WireGuard или AmneziaWG правила работают вместе, выключать VPN не нужно. Правила действуют, пока ProxyBridge запущен, поэтому удобно включить на вкладке «Настройки» сворачивание в трей, чтобы закрытие окна не останавливало программу. Если программа была запущена до того, как ты добавил для неё строку, её уже открытые соединения могли установиться напрямую, поэтому надёжнее её перезапустить. И добавляй в таблицу только то, что действительно должно идти через прокси: каждый лишний процесс тратит трафик провайдера.

Уточнение: режим «весь компьютер» отправляет через один прокси сразу всё, а режим по программам трогает только строки из таблицы и позволяет каждой выдать свой адрес.

Частые вопросы

Как направить одну программу через прокси, а остальные оставить напрямую?

Нужен клиент с режимом по программам. В ProxyBridge на вкладке «Главная» добавляешь программу кнопкой «Добавить программу», выбираешь ей прокси, а строку «Все остальные программы» оставляешь на «Напрямую».

Можно ли сделать разные прокси для разных программ на одном ПК?

Да, у каждой строки в таблице свой прокси. Например, chrome.exe через один адрес, а python.exe через другой.

Почему программа с назначенным прокси всё равно показывает мой IP?

Проверь, что строка включена переключателем и выбран именно тот exe, который работает. Если программа запускает процесс с другим именем, добавь и его, а уже открытые соединения сбрось перезапуском программы.
