Разные прокси для разных программ на одном компьютере

Бывает, что браузеру нужен один IP, мессенджеру другой, а парсеру третий. В ProxyBridge у каждой программы может быть свой прокси, и всё это работает одновременно на одном компьютере. Здесь собрано, как построить такую схему и где у неё границы.

Когда каждой программе нужен свой IP

Разные прокси для разных программ нужны, когда задачи на одном компьютере не должны пересекаться по адресу. SMM-специалист ведёт рабочие аккаунты в разных браузерах, тестировщик сравнивает выдачу сайта в двух регионах параллельно, парсер ходит через серверные прокси и не задевает почту и рабочий мессенджер. Ещё частый случай: корпоративная программа обязана выходить через прокси компании, а всё остальное идёт напрямую. Обратная сторона тоже важна: всё, что не должно идти через прокси (банк, рабочая почта, обновления), продолжает работать с обычного IP и не расходует трафик прокси. Пример раскладки на одном ноутбуке:

  • chrome.exe: резидентный прокси из Москвы для рабочих аккаунтов;
  • firefox.exe: прокси из Казани для проверки региональной выдачи;
  • telegram.exe: отдельный SOCKS5 для второго рабочего аккаунта;
  • parser.exe: серверный прокси для сбора открытых данных;
  • остальные программы: напрямую, без прокси.

Как сделать в ProxyBridge

  1. Переключись в режим Split Tunnel.
  2. Добавь первое правило: имя процесса, например chrome.exe, и его прокси.
  3. Добавь правила для остальных программ, у каждой свой адрес, логин и пароль.
  4. Нажми APPLY SPLIT TUNNELING, чтобы применить все правила сразу.
  5. Открой в каждой программе сервис проверки IP и убедись, что адреса разные.

Как это устроено в Split Tunnel

В режиме Split Tunnel правило состоит из двух частей: имя процесса и прокси. Правил может быть несколько, у каждого свой адрес, свой протокол (HTTP или SOCKS5) и свои логин с паролем. Драйвер смотрит, какой процесс открывает соединение, и отправляет его в прокси из соответствующего правила, поэтому у каждой программы оказывается свой IP. Программы без правила идут напрямую, как будто ProxyBridge не запущен. Недавние прокси сохраняются в истории, и длинные строки не приходится вставлять заново.

Отличие от общего Split Tunnel

Страница о прокси для отдельных программ отвечает на вопрос, как отправить через прокси одно приложение и оставить остальное напрямую. Здесь акцент другой: несколько программ одновременно, и у каждой свой IP. Этот вариант нужен, если ты разносишь аккаунты или задачи по разным адресам и не хочешь держать для этого несколько компьютеров или виртуальных машин. Если программа одна, хватит одного правила, а если весь компьютер должен выходить через один адрес, проще системный режим и кнопка CONNECT.

Что учесть при такой схеме

Правило работает по имени процесса, а не по окну или профилю. Два окна одного Chrome будут ходить через один прокси, поэтому для разных IP используй разные браузеры. Антидетект-браузеры обычно задают прокси для каждого профиля сами, тогда внешнее правило не нужно. Через прокси идёт только TCP, а DNS по умолчанию отправляется напрямую. Перед запуском проверь каждый HTTP-прокси кнопкой VERIFY: она покажет страну, город и внешний IP. SOCKS5 проверяется подключением. Чтобы сменить прокси у одной программы, поправь её правило и снова нажми APPLY SPLIT TUNNELING.

Частые вопросы

Как сделать, чтобы у каждой программы был свой IP?

В режиме Split Tunnel каждой программе назначается свой прокси по имени процесса. Программы без правила идут напрямую с твоего обычного IP.

Можно ли два окна Chrome пустить через разные прокси?

Нет, если это один процесс chrome.exe: правило привязано к имени процесса. Используй разные браузеры или антидетект-браузер, где прокси задаётся для каждого профиля.

Нужен ли отдельный ключ для каждой программы?

Нет, ключ привязан к устройству, а не к правилам. Один ключ работает на двух компьютерах.
