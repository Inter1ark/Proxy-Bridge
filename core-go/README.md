# pbcore

Кроссплатформенное ядро ProxyBridge для macOS и Linux. Один статический бинарник на Go без cgo.

Что делает: создаёт TUN-интерфейс (на macOS это `utunN`), поднимает в нём пользовательский стек TCP/IP и каждое TCP-соединение системы отправляет через один SOCKS5 или HTTP CONNECT прокси. UDP не проксируется (режим "только TCP", как в Windows-версии), кроме DNS: запросы на udp/53 уходят напрямую на резолвер из флага `--dns`, чтобы имена продолжали разрешаться.

Внешние зависимости: `golang.zx2c4.com/wireguard/tun` (MIT) для TUN и `gvisor.dev/gvisor/pkg/tcpip` (Apache-2.0) для сетевого стека. Весь остальной код (SOCKS5, HTTP CONNECT, маршруты, управление) написан с нуля.

## Флаги

| Флаг | По умолчанию | Описание |
| --- | --- | --- |
| `--proxy` | (обязателен) | `socks5://user:pass@host:port` или `http://user:pass@host:port` |
| `--proxy-file` | | прочитать URL прокси из файла вместо `--proxy` (файл удаляется после чтения; так пароль не виден в `ps`) |
| `--tun-name` | `utun` (macOS), `pbtun0` (Linux) | имя интерфейса; на macOS номер выбирается системой |
| `--tun-addr` | `10.255.0.2/24` | адрес интерфейса |
| `--tun-peer` | первый адрес подсети | peer-адрес point-to-point |
| `--mtu` | `1500` | MTU |
| `--dns` | `1.1.1.1` | резолвер, на который напрямую уходит udp/53 (пусто: DNS по UDP отбрасывается) |
| `--route-mode` | `split` | `split`: добавляются маршруты 0.0.0.0/1 и 128.0.0.0/1 через TUN, системный default не трогается. `replace`: default удаляется и подменяется на TUN, при выходе восстанавливается |
| `--control-port` | `34050` | порт управляющего сокета на 127.0.0.1 (0 выключает) |
| `--control-token` | случайный | токен, без которого команды сокета отклоняются |
| `--parent-pid` | `0` | завершиться, когда исчезнет этот процесс (GUI передаёт свой PID) |
| `--stats-interval` | `2s` | период строк `stats` |
| `--log-level` | `info` | `debug`, `info`, `warn`, `error` (в stderr) |

Хост прокси резолвится один раз до изменения маршрутов; для IP прокси и резолвера добавляются host-маршруты через исходный шлюз, чтобы они не попали в туннель.

## Вывод (stdout, по одной JSON-строке)

```
{"status":"up","tun":"utun4","proxy":"socks5://1.2.3.4:1080"}
{"status":"stats","up":12345,"down":67890}
{"status":"error","message":"..."}
{"status":"down"}
```

## Управляющий сокет

Текстовый протокол, одна строка на соединение:

- `stop <token>` остановить и откатить маршруты
- `watch <token>` держать соединение и получать те же JSON-строки, что в stdout
- `ping <token>` ответ `ok`

## Запуск вручную на Mac

```
chmod +x pbcore-darwin-arm64
sudo ./pbcore-darwin-arm64 --proxy socks5://user:pass@1.2.3.4:1080
```

Остановка: Ctrl+C (или `kill -TERM`), маршруты и интерфейс снимаются автоматически. Проверка: `curl https://api.ipify.org` должен показать IP прокси, `netstat -rn | head` покажет маршруты `0/1` и `128/1` на `utunN`.

## Сборка

```
.\build.ps1
```

Соберёт `dist/pbcore-darwin-arm64`, `dist/pbcore-darwin-amd64`, `dist/pbcore-linux-amd64` (прогоняет `go test` и `go vet` для каждой цели).
